# 部署（把服务放到公网，让试用的人能注册）

前提：Node 22+。服务零依赖，不装 npm 包。

## 一、先弄清要暴露什么

- `大报告/原型/`：静态页面
- `大报告/服务/server.mjs`：同时提供静态页 + `/api/*`
- 数据库：`大报告/服务/data/app.db`（SQLite，自动创建）

公网部署时**务必**设置：

| 环境变量 | 作用 |
| --- | --- |
| `ADMIN_TOKEN` | 反馈面板的令牌；不设的话只有本机（127.0.0.1）能看 |
| `HOST=0.0.0.0` | 默认只监听本机；容器里要改成 0.0.0.0 |
| `PORT` | 平台一般会注入 |

## 二、三种常见做法

### A. Render / Railway（最省事）

1. 仓库根目录放 `Dockerfile`（本仓库已带）或直接用 Node 环境
2. Build：`无`；Start：`node 大报告/服务/server.mjs`
3. 加一个持久磁盘，挂到 `大报告/服务/data`（否则每次部署数据清零）
4. 环境变量填 `HOST=0.0.0.0`、`ADMIN_TOKEN=...`

### B. 自己的服务器（阿里云 / 腾讯云 / 一台旧笔记本）

```bash
git clone <your-repo> && cd <your-repo>
HOST=0.0.0.0 PORT=8787 ADMIN_TOKEN=换成随机串 node 大报告/服务/server.mjs
```

前面套个 Nginx 反代到 8787，把 HTTPS 交给 Nginx（服务本身会读 `x-forwarded-proto` 决定 cookie 是否 `Secure`）。

systemd 示例：

```ini
[Unit]
Description=xianjian
[Service]
WorkingDirectory=/opt/xianjian
Environment=HOST=0.0.0.0
Environment=PORT=8787
Environment=ADMIN_TOKEN=change-me
ExecStart=/usr/bin/node 大报告/服务/server.mjs
Restart=always
[Install]
WantedBy=multi-user.target
```

### C. Docker

```bash
docker build -t xianjian .
docker run -d -p 8787:8787 \
  -e HOST=0.0.0.0 -e ADMIN_TOKEN=change-me \
  -v $PWD/data:/app/大报告/服务/data \
  --name xianjian xianjian
```

## 三、上线前要自己过的四条

1. **HTTPS**：没有 HTTPS，密码就是明文过网络。
2. **备份**：`app.db` 是单文件，`cp` 就是备份；设个每日 cron。
3. **令牌**：`ADMIN_TOKEN` 别用 `123456`；它等于全部反馈数据的钥匙。
4. **告知**：页面上那句「勾选同意才上传、随时可删」不是装饰。真上线就该有一页隐私说明，写清存什么、存多久、怎么删。

## 四、现在还没做的（诚实清单）

- 没有邮箱验证、没有找回密码（试用阶段够用，正式上线要补）
- 没有做请求节流之外的反滥用（注册验证码等）
- 没有数据保留期策略（建议：反馈留 12 个月，过期自动删）
- 没有做多实例（SQLite 单文件，多进程写会锁）

## 本机推送踩到的两个坑（2026-11-22）

1. **`git: 'credential-manager' is not a git command`**：Git for Windows 的凭据管理器在
   `C:/Program Files/Git/mingw64/bin/`，某些 shell 里没进 PATH。先
   `export PATH="/c/Program Files/Git/mingw64/bin:$PATH"`，再用 `-c credential.helper=manager` 推送即可静默完成。
2. **`fatal: unable to auto-detect email address`**：新仓库要先 `git config user.name/user.email`（本仓库用的是
   `0-OsealO-0` 与 `0-OsealO-0@users.noreply.github.com`）。
3. 顺带记录：设备授权（device flow）拿到的令牌**能推送但不能建仓库**（`403 Resource not accessible by integration`），
   所以仓库是先手动建的，推送由 `dev/wait_and_push.py` 完成。

## 部署到 Render（推荐路径，一条命令都不用敲）

仓库里已经有 `render.yaml`，Render 会照它建服务、挂盘、设环境变量。

1. 打开 https://dashboard.render.com/blueprints → **New Blueprint Instance** → 选仓库 `0-OsealO-0/xianjian`
2. 它会读 `render.yaml`，只让你填一个变量：**`ADMIN_TOKEN`**（自己想一串，别用 `123456`）
3. 点 **Apply**，等 2–3 分钟；状态变绿后访问 `https://<服务名>.onrender.com`
4. 自检：`/api/health` 返回 `{"ok":true,...}`；打开 `/index.html` 能走流程；`/admin.html` 输 `ADMIN_TOKEN` 能看到汇总

**注意两点**

- `render.yaml` 里写的是 `plan: starter` + 1 GB 盘：因为 **免费实例的文件系统是临时的**，重启/重新部署会把 SQLite（账号、反馈）清空。想要数据留得住，用 Starter（约 $7/月）；要严格零成本，走下面的隧道方案。
- 服务起来后，把 `HOST=0.0.0.0`（yaml 里已设）留给容器；本机跑仍然是 `127.0.0.1`，别人访问不到。

## 零成本替代：本机 + 隧道（试用期够用）

数据全留在你电脑上（`大报告/服务/data/app.db`），只把端口临时暴露成 https：

```bash
# 1) 起服务
node 大报告/服务/server.mjs          # 或双击 大报告/启动服务.cmd

# 2) 另开一个窗口，把 8787 暴露出去（首次会自动下载 cloudflared）
npx cloudflared tunnel --url http://127.0.0.1:8787
```

它会打印一个 `https://xxx.trycloudflare.com` 的地址，发给同学就能用；**你的电脑关机或关掉窗口，链接立刻失效**。
试用期这样最省事，也最符合「数据留本机」。

## 试用前的最低检查

- [ ] `/api/health` 的 `cookie` 为 `true`（说明 B 站搜索可用；为 false 时「在 B 站找 3 个候选」会退回搜索链接）
- [ ] 注册 → 不勾同意 → 发反馈被拒（403 文案）→ 勾上 → 成功
- [ ] `/admin.html` 能看到数字与反馈，CSV 能导出
- [ ] 手机打开一次，确认步骤条与按钮没挤坏

## 2026-11-22 实际采用的部署：Railway + Cloudflare D1

线上地址 <https://xianjian-production.up.railway.app/>（区域 US East，Railway 免费试用 30 天 / $5 额度）。

### 为什么不是 Workers / Render
- `*.workers.dev`：本地 DNS 解析到 `108.160.167.147`（投毒），换成 Cloudflare 真实 IP 直连也全部超时 —— 国内不可达。
- Render 免费实例：创建服务前强制要求绑定信用卡（临时授权 $1），不符合「免费不绑卡」。
- `*.vercel.app`、Netlify、Deno、Fly.io、Supabase：同批测试均不通；`onrender.com` / `up.railway.app` / `zeabur.app` / `*.hf.space` 通（但 Hugging Face 主站在国内被墙）。

### 结构
- Render/Railway 这类免费 Web 实例**没有持久磁盘**，所以数据库不落在实例上：`大报告/服务/server.mjs` 检测到 `CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID + D1_DATABASE_ID` 就切到 D1 HTTP API（`store.mjs` 里 `usingD1` 分支），否则用本机 SQLite。
- 两套后端接口完全一致（全部 async），本地和线上跑的是同一份 `api.mjs`。

### Railway 侧配置
| 项 | 值 |
|---|---|
| 构建 | Nixpacks，`npm install`（无依赖，秒过） |
| 启动 | `npm start` → `node 大报告/服务/server.mjs`（根 `package.json`） |
| 环境变量 | `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、`D1_DATABASE_ID`、`ADMIN_TOKEN`、`HOST=0.0.0.0`、`PORT=8787` |
| 端口 | 公共网络目标端口 **8787**（必须与 `PORT` 一致，否则 502） |

> 坑：Railway 自己会注入一个 `PORT`，如果不显式写 `PORT=8787`，应用听在注入端口、域名转发到 8787，就会一直 502。

### D1 侧
- 库名 `xianjian`，`database_id=4779567b-113a-4219-b3a1-f2d10185859f`，表由 `migrations/0001_init.sql` 建好（users / sessions / feedback / events）。
- Worker 版（`workers/`）已经部署但**国内不可达**，仅作备份；两边共用同一个 D1 库，所以数据一致。

### 凭据放哪
- 本机：`大报告/服务/workers/cf.local.json` 与 `accounts.txt`（都在 `.gitignore` 里，绝不入库）。
- 线上：Railway 的 Variables（加密存储，页面只显示 `*******`）。

### 踩过的坑：Railway 的 GitHub 集成会失效（线上不更新的真正原因）

症状：`git push` 成功，但线上一直是旧版本；Railway `Settings → Source` 里显示

- `Auto deploy unavailable` / `Auto deploy is disabled`
- `Could not load branches`（红叉）

原因：Railway 的 GitHub App 对仓库的授权掉了（重新授权过 GitHub OAuth、或仓库是后建的都可能触发）。
只点 **Retry** 没用，必须重装一次 GitHub App：

1. 打开 `https://github.com/apps/railway-app/installations/new`
2. 仓库访问选 **All repositories**（选 `Only select repositories` 但一个仓库都没勾时，`Install & Authorize` 是灰色的、点不动——这是最容易卡住的地方）
3. GitHub 可能要求 sudo 模式：输入账号密码确认（这一步只能本人做）
4. 回 Railway `Settings → Source`，`Could not load branches` 消失
5. 把 `Auto deploy` 点 **Enable**（会变成 `Auto deploys when pushed to GitHub`）
6. 推一个空提交（`git commit --allow-empty`）触发一次部署，等 2–3 分钟

验证新版本是否真的上线的两个快速信号：

- `curl https://<域名>/index.html | grep -o "account.js?v=[0-9]*"`：版本号应该是最新的
- `curl -s -o /dev/null -w "%{http_code}" https://<域名>/api/progress`：新代码应返回 **401**（旧代码是 404 `没有这个接口`）
