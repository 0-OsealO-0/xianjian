# 先见 · 项目构想 v0.2

> 一句话：**先给学生一张方向地图，再用他自己的问题，把他拖回基础。**
> 定位：一个内置于大模型 Agent 的本科学习引擎——不是课表，不是问答机器人，是一条学生自己跑得起来的路径。

---

## 一、我们要解决的问题

今天本科的默认路径是「基础课 → 专业课 → 实习 → 考研或就业」。问题不在某一门课，而在**路径的形状**：太长，也太窄。

- **太长**：一个学生往往到大三才第一次接触"这个专业到底能解决什么问题"。等他明白每天在学什么，时间已过去大半。
- **太窄**：所谓优秀只有一个定义——在既有轨道上更靠前一点。创新的空间不在路径的设计里，只是被期待从尽头自己长出来。

更麻烦的是**思维惯性**：高中有一套终点明确、兑换关系可算的评价体系；大学没有终点。考完最后一场试，前面就没有跑道了。很多人还在用旧尺子量新路——"保研了没有"，而不是"我最后要往哪个方向走"。

**AI 改变了哪一环？** 过去一个天马行空的想法，判断它可不可行代价极高：要么自己学完，要么等到遇见懂的人。现在可以把它交给 AI，拿到方案、被指出漏洞、甚至跑出一个粗糙原型。真正关键的是**之后发生的事**：为了看懂 AI 说了什么、错在哪里，学生必须回头补知识。这样的补，是被问题拖出来的，不是被课表推着走的。

于是形成闭环：**想法 → 验证 → 被证伪 → 补基础 → 调整想法 → 再验证**。几轮下来，知识是自己长出来的，方向也是自己走出来的。

这一步有实证支撑：PNAS 2025 一项近千名高中生的随机对照实验发现，无约束的 GPT-4 让练习时成绩提高 48%，但收走 AI 后考试反而比从未用过的人低 17%；而加了"只给提示、不给答案"的护栏后，练习成绩提高 127%，考试不再受损（Bastani et al., *PNAS* 2025, 10.1073/pnas.2422633122）。**结论不是"AI 有害"，而是"护栏决定方向"**——我们做的正是护栏那一侧。

## 二、产品是什么

**先见**是一个四步闭环的工具，可以做成网页，也可以做成嵌入 Agent 的技能/插件：

| 步 | 名字 | 学生做什么 | 工具给什么 |
|---|---|---|---|
| 1 | **看见地图** | 输入学校、专业、年级、兴趣、已修课程 | 该专业 6 个真实方向：每个方向在解决什么问题、代表成果、需要的前置知识、对应课程、校内可对接的资源 |
| 2 | **你现在到哪了** | 勾「学到哪了」——精确到知识点，不用勾整门课 | 三态进度（没学/在学/学过）+ 由此算出的知识缺口 |
| 3 | **手头这一件事** | 只做当前这一件（20–60 分钟），做完点"做完了" | 一件任务 + 为什么现在做它 + 怎么做 + 做完后的追问 |
| 4 | **被审查** | 写一句话回答追问 | **诊断而非打分**：哪块接住了、哪块是空的、下一件是什么 |
| 5 | **回到想法** | 改写/收窄/放弃原来的想法 | 自动记录版本链（v1 被推翻 → v2），把"证伪"沉淀成资产 |

**四条设计原则**（决定了它和"AI 答疑工具"不是一类东西）：

1. **先给地图，不给答案。** 第一步永远不是"你要学什么"，而是"这个专业能做什么"。
2. **知识由问题拖出来。** 每个知识点都挂在某个具体问题上，没被问题击中的知识不出现。
3. **审查看过程，不看产出。** 输入是版本链、失败记录、决策改动的理由，而不是最后的报告。
4. **考核产出是诊断，不是分数。** 代做拿不到有用诊断，代做的动机就掉了——这是我们的反作弊机制，不是附加功能。

## 三、v0.2 做了什么（现在就能看）

`大报告/原型/` 是一个**可直接双击打开**的可交互原型（纯前端，无需安装、无需联网、无需 API Key）。v0.2 是按第一轮真实反馈重做的，核心变化是**从"一次铺开整条路"改成"一次只给一件事"**：

- **六条路**：通信与网络 / 信号与信息处理 / 微电子与集成电路 / 电磁场与微波 / 光电与显示 / 智能信息处理。每张卡只写「在解决什么问题」+「会用到哪些你还没学的知识」（按你的进度实时算）。
- **知识点粒度**：14 门课、35 个知识点，每个可标「没学 / 在学 / 学过」——高数只学了极限就勾极限，不用勾整门课。
- **目标卡**：一句目标 + 一共几件 + 按你的周投入估算几天 + **只给第一件**。不预演整条路。
- **任务级滚动**：每件 20–60 分钟，带"为什么现在做它"和具体 3–4 步做法。做完立刻一道追问（写一句话即可），然后给"你刚刚拿到了什么"+ 进度 + 下一件。
- **缺什么插什么**：任务里写了自己依赖哪些知识点；没学过就在前面自动插一条「补一块地基：随机变量与分布」。补完之后，后面的路径自动变短——**计划是随状态现算的，不是写死的**。
- **矩阵彩蛋**：从"我到现在也没搞懂矩阵用来干什么"出发，矩阵在该专业真实出现的三个位置（DFT 矩阵、MIMO 信道矩阵的 SVD、卷积的 Toeplitz 形式）。
- **换屏不闪**：用 View Transitions 做淡入；知识点的三态切换是就地改 class，不重绘整页。

> 现状边界：v0.2 的数据与流程是真的，**判读层是关键词规则**（命中 ≥1/3 算接住），不理解语义；模型接入在 v1。

## 四、和现有产品差在哪

| | 可汗学院 / Khanmigo | AI 家教类产品 | **先见** |
|---|---|---|---|
| 入口问题 | "这道题怎么做" | "这个知识点怎么讲" | **"这个专业能做什么"** |
| 知识组织 | 按课程大纲 | 按知识点 | **按方向与问题** |
| 考核 | 练习正确率 | 测验分数 | **过程审查 → 诊断** |
| 结果 | 学会某章 | 提分 | **长出一个自己的方向** |

我们不做"更好的讲义"。我们做的是**先让人看见地图**——因为学生现在最缺的不是更清楚的讲解，而是一个能让他提前碰上矩阵的问题。

## 五、技术架构

**v0.2（已完成）**：静态前端（HTML/CSS/JS）+ JSON 数据层 + 任务链引擎 + 规则判读 + localStorage 存档。零依赖、可离线演示。

**v1（目标形态）**：

```
前端  Next.js（网页）+ 微信小程序壳（可选）
      ↓
后端  FastAPI
      ├── 画像服务：专业/年级/已修课/兴趣 → 方向候选
      ├── 图谱服务：方向-问题-知识-课程 四层图（Neo4j 或 SQLite 图表）
      ├── 规划服务：知识缺口 + 每周时长 → 只生成「下一件事」
      ├── 审查服务：LLM 追问 + 过程证据打分 + 人类抽检队列
      └── 诊断服务：把薄弱点写回图谱，触发下一轮
      ↓
模型  OpenAI 兼容接口（可换 DeepSeek / 通义 / 智谱）
      向量库 用于教材片段与项目案例检索（RAG）
```

**关键技术判断**：
- 图谱必须**结构化存储**，不能全靠模型自由生成——否则每次回答不一致，也无法做依赖闭合检查。这正好用上符号主义那套（知识表示 + 推理）。
- 审查必须**双通道**：模型追问 + 过程证据（版本链、提交记录、失败日志）。单靠模型的面试一定可被代答。
- 计划生成要**可解释**：每一条都能回答"为什么这周学这个"。

## 六、8 周 MVP 与里程碑

| 周 | 目标 | 交付物 | 验收标准 |
|---|---|---|---|
| 1 | 方向图谱 v1 | 电子信息 6 方向 × 问题/知识/课程/资源 | 6 个方向数据齐全，能被他人复核 |
| 2 | 画像与匹配 | 输入表单 → 方向推荐 | 3 个真实同学试用，推荐不至于离谱 |
| 3 | 任务链引擎 | 按知识状态现算的下一步 | 改一个知识点的状态，下一步会跟着变 |
| 4 | 审查器 v1 | 18 题追问 + 诊断输出 | 诊断能指出具体缺口，而非"还需努力" |
| 5 | 模型接入 | LLM 追问 + RAG 教材片段 | 同一问题两次回答结构一致（有约束） |
| 6 | 过程证据 | 版本链 + 提交记录接入 | 能区分"做过"和"没做过"的回答 |
| 7 | 小程序/网页上线 | 可分享链接 | 手机端可用，加载 < 2s |
| 8 | 小规模试点 | 5–10 人跑完一个完整闭环 | 至少 3 人产出可展示的项目雏形 |

**成功指标**（不是 DAU）：完成一次完整闭环的人数、每人产出的项目数、审查诊断被学生认为"准确"的比例。

## 七、招募：我们在找谁

**五个角色，可重叠，每周投入 4–8 小时**：

| 角色 | 要做什么 | 需要会 | 你会得到 |
|---|---|---|---|
| 前端 | 网页/小程序界面，把四步做成好用的东西 | React 或原生 JS + CSS，愿意抠细节 | 一个真实上线的产品经历 |
| 后端 | 图谱、计划生成、审查队列 | Python/FastAPI，SQL，基本算法 | 图数据建模与 LLM 工程经验 |
| LLM/Agent | 追问策略、护栏、诊断输出、RAG | Prompt 工程，了解 function calling | Agent 产品从 0 到 1 的完整链路 |
| 教育研究 | 方向数据、审查标准、访谈与评估 | 愿意读文献、做访谈、写清楚 | 教育测量与定性研究的实操 |
| 设计 | 信息架构、视觉、演示 | Figma 或直接写 CSS | 一份能放进作品集的 case |

**我们提供**：一个真实的选题（不是课程作业式的虚构需求）、可以写进简历的工程实践、每周一次 60 分钟的同步会、以及**署名权**——每个人的贡献都会在 README 与演示里明确标注。

**我们在找的人不是"技术最强的"，而是"自己也想知道方向在哪的"**——因为这个工具的第一个用户就是我们自己。

## 八、风险与对策

| 风险 | 判断 | 对策 |
|---|---|---|
| AI 考官可被代做 | 高，且是致命的 | 过程证据 + 出题评分分离 + 人类抽检 10% + 诊断而非打分 |
| 基础空洞化 | 中高 | 每个项目强制附"知识依赖清单"，审查时检查是否闭合 |
| 只服务优势学生 | 中 | 不选拔、只设投入门槛（公开过程 + 每周固定时长）；优先无导师资源、跨专业的学生 |
| 学分与制度接口 | 高，但不紧急 | 三步走：工作坊 → 挂靠现有课程作业 → 学分认定试点。不把制度当前提 |
| 方向漂移 | 中 | 每 4 周一次复盘，允许改方向，但要求写清"为什么改" |
| 课程成绩受影响 | 中低 | 基础知识总量有限，但必须有下限检查：每学期一次"基础体检" |

## 附：演示脚本（5 分钟，招人时照着讲）

**0:00–0:40 开场（一句痛点）**
"我问你一个问题：你大三的时候，能不能说出你们专业在解决哪三个真问题？大多数人说不出。不是不努力，是路径太长——先学三年基础，才第一次看见方向。"

**0:40–1:40 只演示一件事：地图**
打开原型，进「六条路」。不说功能，说**内容**："这是电子的六个方向，每个方向我写的是*它在解决什么问题*，不是就业岗位。"
停在「矩阵」卡片上，念那句："如果你也在想矩阵到底用来干什么——"点开，读 MIMO 那一条：H = UΣVᴴ，秩决定你能开几条车道。**"我大二的时候没人告诉我这句话。"**

**1:40–2:40 诊断：把"差距"变具体**
随手勾几个知识点（比如只勾了极限），选一条路。指着卡片："它不告诉你'要努力'，它告诉你*你缺随机变量*，因为下一步要给信号加噪声。"
再点「做完了」："看，它没让你一次学完，它只给你下一件事；补完这块地基，后面的路自己变短。"

**2:40–3:40 审查：全场最反直觉的一步**
进审查，故意答错一题（或答"不知道"）。指着诊断卡："这里没有分数。分数可以背、可以代做；'你哪块知识是空的'不能。这就是我们的防代做机制。"
补一句实证："PNAS 2025 的实验：无护栏的 GPT-4 让练习成绩涨 48%，收走后考试掉 17%；加了护栏反而涨 127% 且不损伤考试。护栏长什么样，就是这个。"

**3:40–4:30 闭环：版本链**
在闭环页写一句想法、存为 v1，再写一个更窄的 v2，展示版本链。"被证伪不是失败，是这个系统里唯一产生信息的事件。这条链也是将来判断'是不是你自己做的'的证据。"

**4:30–5:00 收尾（招人，不说"求加入"）**
"现在能跑的是数据和流程，模型还没接。我要找的不是技术最强的，是**自己也想知道方向在哪的人**——因为这个工具的第一个用户就是我们自己。前端、后端、LLM、教育研究、设计，各一个就够，每周 4–8 小时。"
最后一句留白："如果你听完第一反应是'我当年要是有这个'——那你就是我们要找的人。"

**演示时的三个坑**
1. 别一上来讲架构，讲**内容**（矩阵那条比任何架构图都有说服力）。
2. 别承诺"能提分"，承诺"能帮你想清楚要不要走这条路"。
3. 被问"和 ChatGPT 有什么区别"——答："ChatGPT 回答你的问题；这个先告诉你该问什么问题。"
